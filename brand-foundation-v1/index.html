    Who Is It For?

    We serve two audiences. One is primary — the people we build for first. The other is secondary — the people who benefit indirectly but are essential to the ecosystem.

    Open decision

    Who the primary audience is has not been settled. The two candidates below go into an A/B test on the landing page — one variant written for each — and the variant that converts settles the question. Until the test reports, the primary audience card below stays empty rather than assuming an answer.

    Variant ABuilders & Creators

    People who build agents, skills and tools. Narrower, more technical, and the audience the Marketplace and the skill economy are built for. Documented in the card below.

    Variant BGeneral public (retail)

    People who already use several AI tools and want one that decides for them. Far larger, far less technical, and the audience Conductor Mode and Guest Mode speak to.

    Product Language

    How we name and describe each product surface — the vocabulary that ties the platform together.

    Product One-line description What it does Voice note
    Conductor Mode Starchild choosing the right AI for each step of a task Reads the whole task, picks the model and tools built for it, checks the result, returns one answer Never explain routing, tokens or model names. "Starchild chooses the right AI for each task, so you don't have to."
    Agent Work that carries on after the conversation ends Keeps track of something, repeats it, or takes care of it over time Not a "bot". The page says it plainly: "Let Starchild keep things moving for you."
    Marketplace Where skills are discovered, used and published Browse what others built, or list your own and get paid each time it runs Community first — not an app store, a gathering
    Skill Something Starchild did once, packaged so it can be run again Anything Conductor built for you — a poster, a brand kit, a fix — becomes a skill of its own Like a plugin, but warmer and more open
    MCP Not built Model Context Protocol — the connection standard Would connect any agent to any tool via a shared protocol. Nothing in the product uses this word yet The plumbing nobody sees but everyone needs. Keep it out of user-facing copy until it exists

    Landing Page Validation Loop

    Before we build the full site, we validate the core message with a minimal landing page. This is the loop: build → test → learn → iterate.

    1

    Build

    Ship the landing page and the product behind it. There is no waitlist — every call to action drops straight into Guest Mode, so the message is tested against the product, not against a form.

    →
    2

    Test

    Drive real traffic. The first thing the page runs is the audience A/B test — variant A for builders, variant B for the general public. Watch where people click, where they leave, what they sign up for.

    →
    3

    Learn

    What landed? What confused? What made them stay? Document the signals.

    →
    4

    Iterate

    Refine the message based on evidence, not opinion. Then run the loop again.
